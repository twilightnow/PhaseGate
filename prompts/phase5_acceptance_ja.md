# Phase 5：受入検証

## あなたのタスク

Phase 0 で定義されたすべての受入基準をプロジェクトが満たしていることを検証してください。
このフェーズには 2 つのサブステージがあります：AI 自動検証（5A）は完全自動で実行し；人工検証ガイド（5B）はユーザーが手動で完了できるよう生成します。

---

## 開始前に読み込むもの

1. `.phasegate/requirements/*.md` — すべての `Acceptance Criteria` チェックリスト項目を抽出する
2. `.phasegate/progress.md` — **Phase 3 Summary** と **Phase 4 Summary** ブロックをコンテキストアンカーとして読み込む；どのモジュールが `done` か `failed`/`blocked` かを確認する
3. `.phasegate/scratchpad/*/report.md` — すべての完了モジュールの worker 報告書（カバレッジ、既知の issues）

---

## Phase 5A：AI 自動検証

### Step 1：受入基準の分類

`.phasegate/requirements/*.md` のすべての受入基準を解析する。
それぞれを **自動検証可能** または **手動確認必須** としてラベリングする：

| 自動検証可能 | 手動確認必須 |
|---|---|
| 機能：特定の入力に対して期待値と一致する出力 | UX：ユーザー体験、視覚的判断 |
| エラー処理：正しいエラーコード/メッセージの返却 | 主観的品質："メッセージが明確" など |
| カバレッジ：テストカバレッジ ≥ 閾値 | サードパーティ統合：ライブの外部サービス呼び出し |
| 制約：循環依存なし・≤ 500 行 | 実負荷でのパフォーマンス（自動ベンチマークで網羅されていない場合） |
| すべてのユニットテストが通過 | ビジネス承認：担当者によるサインオフ |

チェックを実行する前に分類済みリストを生成する：

```
自動検証可能：
  [AC-01] すべてのユニットテストが通過している
  [AC-03] リソースが見つからない場合に 404 を返す
  ...

手動確認必須：
  [AC-02] エラーメッセージがユーザーフレンドリーである
  [AC-05] モバイル画面で正しく動作する
  ...
```

`failed`/`blocked` モジュールが存在する場合、それらのために検証できない受入基準を明記する。

---

### Step 2：自動チェックの実行（順番通りに）

以下をそれぞれ実行する。ステップが失敗した場合、直ちに自己修正ループに入る。

**2-A. すべてのモジュールテストを実行する**
```
npm test
```
- すべての `done` モジュールのテストが 100% 通過（失敗なし、スキップなし）
- モジュールごとのカバレッジ ≥ 80%

**2-B. constraint-checker を実行する**
```
phasegate status
```
違反ゼロを期待する：
- [ ] 500 行を超えるファイルなし
- [ ] 循環依存なし
- [ ] クロスモジュール内部 import なし
- [ ] すべての公開シンボルに型付け

**2-C. 自動検証可能な受入基準を検証する**
自動検証可能な各基準について、対応するテストまたは検証コマンドを実行し、通過することを確認する。

---

### Step 3：自己修正ループ（Step 2 の失敗時に起動）

```
1. テスト/制約出力から失敗しているモジュールを特定する
2. phase3_worker.md をシステムプロンプトとして使用し、そのモジュールの worker agent を再 fork する：
     - .phasegate/tasks/{module}.md
     - 関連する契約（consumers frontmatter から）
     - docs/03_architecture_constraints.md
     - 失敗の説明：正確なテスト出力または制約違反レポート（注入コンテキストに追加）
3. Worker が問題を修正し、報告書を .phasegate/scratchpad/{module-name}/report.md に再提出する
4. 失敗したチェックを再実行する
5. PASS → 残りのチェックを続ける
   FAIL（試行 2 回目）→ 追加の失敗コンテキストでもう一度再試行する
   FAIL（試行 3 回目）→ エスカレート：Phase 5A を一時停止し、完全な失敗記録をユーザーに報告する
```

モジュールごとの最大自己修正試行回数：3 回。3 回目の失敗後は、それ以上の修正を試みないこと — 無条件にエスカレートする。

---

### Step 4：Phase 5A 検証レポート

Phase 5B に進む前に以下を出力する：

```
Phase 5A 自動検証結果
===================================
[PASS] すべてのユニットテストが通過（N テストケース、M 完了モジュール）
[PASS] アーキテクチャ制約：違反 0 件
[PASS] AC-01: {基準テキスト}
[PASS] AC-03: {基準テキスト}
[SKIP] AC-06: {基準テキスト} — 検証不可；module-x が Phase 3 で失敗
[ESCALATED] AC-04: {基準テキスト} — 3 回の試行後も自己修正失敗；手動レビュー必須

サマリー：N/M 件の自動検証基準が通過、K 件スキップ、J 件エスカレート
```

エスカレートされた基準がある場合は、Phase 5B の受入ガイドにエスカレートメモを含めること。

---

## Phase 5B：人工検証ガイドの生成

Phase 5A が完全に完了した後（すべてのチェックが PASS・SKIP・ESCALATED — 保留なし）にのみここに進む。

プロジェクトルートに `acceptance-guide.md` を生成する：

```markdown
# {project-name} 受入ガイド

生成日：{date}
フェーズ：5B — 人工検証

## AI 自動検証サマリー
- [x] すべてのユニットテストが通過（{N} テストケース、{M} モジュール）
- [x] アーキテクチャ制約チェック：違反 0 件
- [x] {各通過した自動検証可能な受入基準}
- [ ] {各エスカレートまたはスキップされた基準 — 理由を注記}

## 人工検証が必要な項目

### {N}. {要件からの基準テキスト}
**検証方法：**
{人間が実行するための番号付きステップバイステップの手順}

**期待される結果：**
{実装が正しい場合に検証者が観察すべきもの}

**合格条件：**
{この基準が通過するための明確で曖昧さのない条件}

---

## カバーされていないモジュール

以下のモジュールは Phase 3 で失敗またはブロックされており、このガイドには含まれていない：

| モジュール | 状態 | 理由 |
|---|---|---|
| module-x | failed | {Phase 3 Summary からの理由} |
| module-y | blocked | module-x の下流 |

これらのモジュールに依存する受入基準は、それらのモジュールが修正された後に再評価する必要がある。

---

## エスカレートされた項目（人工 + AI による調査が必要）

| 基準 | 失敗の概要 | 自己修正試行回数 |
|---|---|---|
| AC-04 | {説明} | 3 回（すべて失敗） |
```

---

## 人工検証後（次の AI セッション）

ユーザーが結果を報告する。以下のように対応する：

| 結果 | 対応 |
|---|---|
| すべて通過 | `PHASE_DONE` を含む Phase 5 Summary を `progress.md` に追記する |
| バグが見つかった | 関連するモジュール worker を再 fork（Phase 5A と同じ自己修正ループ）；修正後にそのモジュールのテストと制約チェックを再実行；修正後に影響を受ける人工検証基準を再検証する |
| 設計上の問題が見つかった | `.phasegate/requirements/{fix-name}.md` を作成する；既存の作業をロールバックしない；影響を受けるモジュールのみ Phase 1→2→3 を実行する；それらのフェーズが完了した後、Phase 5 に戻り影響を受けるモジュールのすべてのチェックを再実行する |

---


## フェーズチェック

### Gate 5A — 受入ガイド生成前に確認（最初のセッション終了）
- [ ] すべての自動チェックが完了：PASS・SKIP・ESCALATED のいずれか — 保留なし
- [ ] アーキテクチャ constraint-checker：すべての完了モジュールで違反 0 件
- [ ] Phase 5A 検証レポートをユーザーに出力済み
- [ ] プロジェクトルートに `acceptance-guide.md` を生成済み

### Gate 5B — 人工検証結果の受領後に確認（2 回目のセッション）
- [ ] ユーザーが受入ガイド内のすべての検証可能項目を確認・報告済み
- [ ] 手動検証中に見つかったバグが修正・再検証済み
- [ ] `PHASE_DONE` を含む Phase 5 Summary を `.phasegate/progress.md` に追記済み

---

## 終了時の行動（厳守）

### Phase 5B が `acceptance-guide.md` を生成した後（最初のセッション終了）
- すべての自動検証チェックが完了したことをユーザーに伝える
- `acceptance-guide.md` のパスを提供する
- ガイドに従って人工検証を完了するようユーザーに指示する
- 「次は何かしますか？」などの質問を**禁止**する
- 制御をユーザーに返し、検証結果を待つ

### 人工検証結果を受け取った後（2 回目のセッション終了）
- プロジェクトがすべてのフェーズを完了したことをユーザーに確認する
- 既知の制限（失敗/ブロックされたモジュール）を報告する
- 元の要件の範囲を超えた新機能の開始や次のステップの提案を**禁止**する
- 制御をユーザーに返す
